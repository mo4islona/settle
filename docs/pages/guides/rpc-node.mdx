# Use with an RPC node [Read blocks from a JSON-RPC node and find forks yourself]

<LanguageSwitch label="Code language" />

An RPC node gives you one block at a time. It does not tell you when the chain replaces blocks. Your app must find a fork itself. A fork occurs when the parent hash of a new block is not the hash of the last block that your app sent.

This guide shows a full loop with plain JSON-RPC calls: `fetch` in TypeScript, `ureq` in Rust. You can use the same method with another client, for example viem or alloy. The example keeps the number of blocks and the gas of each fee recipient on Ethereum.

:::code-group

```bash [TypeScript]

npm install --save-dev tsx
```

```bash [Rust]

cargo add serde_json@1
cargo add ureq@2 --features json
```

:::

The loop keeps the last block that it sent in `last`. At the start, `last` is <Api ts="db.cursor" rust="db.latest_cursor()" />, the last block that Settle has. For each new block, the loop compares the parent hash with the hash of `last`:

When the hashes are equal, the new block follows the last block. The loop sends it to Settle with its hash and the last final block.

### Handle a fork

When the hashes are not equal, the chain replaced the last block, or more blocks. The loop gives Settle the blocks of the new chain, from the last block down. Settle finds the last block that the two chains have in common, and undoes the blocks above it:


:::

- <Api ts="resolveForkCursor" rust="resolve_fork_cursor" /> looks for a common block in the chain that you give. It changes nothing.
- When it finds no common block, the loop reads more blocks, but not below the last final block. A fork cannot replace a final block.
- <Api ts="handleFork" rust="handle_fork" /> does the rollback. It returns the common block and the changes that undo the blocks above it.
- The loop then continues after the common block, and reads the blocks of the new chain.

When the chain down to the last final block has no common block, <Api ts="handleFork" rust="handle_fork" /> fails. Then the node and Settle do not agree about a final block. Stop the app and find the cause.

## Run it

:::code-group

```bash [TypeScript]
RPC_URL=https://ethereum-rpc.publicnode.com npx tsx rpc-node.ts
```

```bash [Rust]
RPC_URL=https://ethereum-rpc.publicnode.com cargo run --release --bin rpc-node
```

:::

On a new database, the loop starts at the last block of the chain. Set `START_BLOCK` to start at a different block. The loop reads each block one by one, so it is slow for a long history. To read a long history, use a source that gives many blocks in one request, for example [SQD Portal](/guides/sqd-portal).
